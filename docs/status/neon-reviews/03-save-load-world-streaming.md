### 1. Disk `MeshCache` drops all mid-range LOD counters (`blobFar*`, `farPlants`, `canopy*`) — disabling far-tree/plant LODs on cached launches + `have`-before-write race deletes fresh cache files
- **Evidence:**
  - `Sources/ChunkShells.swift:145-159,209-212,310-321`: `MeshCache` (`format = 5`, `countsPerSection = 16`) serializes `opaqueQuads`, `solidQuads`, `farSkip`, `farExtra`, `transQuads`, `detailQuads`, `detailSolid`, `naturalCubes`, `groundQuads`, `blobQuads`, `solidFull`, `farCut`, `detailFarSkip`, `detailFarExtra`, `farTail`, and `deferred` — **omitting** `s.blobFarAt`, `s.blobFarN`, `s.blobCutN`, `s.farPlants`, `s.canopyN`, and `s.canopyTrunks`.
  - `World.installShell` (`Sources/ChunkShells.swift:152`) explicitly resets `s.farPlants = 0` and leaves `blobFarAt`, `blobFarN`, `blobCutN`, `canopyN` at `0`.
  - In `quest/src/vk/SceneRenderer.swift:2229-2230,2767,2780-2781,2937-2960`, `band` (swapping double-shell alpha-tested cutout leaves for simplified solid far leaf blobs past `blobFarFrom = 64` blocks) requires `e.bN > 0`, and `plantsOut` (skipping small grass/flowers/seagrass/kelp past `plantFarFrom = 64` blocks) requires `e.pN > 0`.
  - Result: on every saved-world launch, teleport, or return to explored land, **every shell-band chunk loaded from `MeshCache`** draws 100% full near-detail alpha-tested cutout foliage (`chunk_cut.frag`, disabling Early-Z) and all small ground/water plants all the way out to 180 blocks — while still paying VRAM for the unused `blobFar` vertices already baked into `opaqueBuf`.
  - **Cache race & size drift (`Sources/ChunkShells.swift:324-350,372-390`):** `MeshCache.write` inserts `k` into `have` synchronously (`:324`) *before* `queue.async` writes `m.X.Z.bin`. If the player moves back before the utility queue finishes writing, `mc.has(k)` returns `true`, a worker calls `mc.read(k)` (`:374`) → ENOENT → `drop(k)` removes `k` from `have` and appends `removeItem(at: u)` onto `MeshCache.queue` **after** the pending write, deleting the freshly written cache file immediately after it lands. Line `348` (`bytes += d.count`) also double-counts overwrites without subtracting the previous file's size, triggering premature `trim()` directory scans.
- **Recommended fix:** Bump `MeshCache.format` to `6` and `countsPerSection` to `24`, serializing `blobFarAt`, `blobFarN`, `blobCutN`, `farPlants`, `canopyN`, and `canopyTrunks` (3 ints) in `MeshCache.write` and restoring them in `World.installShell`. Move `have.insert(k)` inside `queue.async` **after** `Data(d).write(to: u, options: .atomic)` succeeds (so `read` never races an in-flight write), and subtract any existing file size before `bytes += d.count`.
- **Expected effect:** Restores P453 far leaf blobs and Nov 6 small-plant/seagrass culling on every saved-world launch/teleport (preventing unexpected GPU drops and `ViewGovernor` view-distance dips on revisited worlds) and eliminates self-deleting cache files.
- **Risk:** Low (bumping `MeshCache.format` cleanly invalidates older cache files on upgrade; saves themselves are untouched).

### 2. Ledger 383's `deepWaterAbove` deep-sea culling silently turns OFF on every hollow chunk shell — defeating it across the exact outer ocean band it targets
- **Evidence:**
  - `quest/src/vk/SceneRenderer.swift:2225,2245-2257` (Ledger 383 on `origin/claude/quest-port`): `deepWaterAbove(_ c: Chunk, _ sy: Int)` inspects `c.blocks[Chunk.index(x, y, z)]` and `c.blocks[Chunk.index(x, y + 10, z)]` during `fillColumn`.
  - `Sources/ChunkShells.swift:24,64-77`: once any chunk past `keepDataDistance` (`min(activeDistance, renderDistance) + 2`, i.e., 96–160 blocks) finishes meshing, `World.hollow` clears `c.blocks = BlockStore([])` and sets `c.hollow = true`.
  - `Chunk.hollow.didSet` (`Sources/Chunk.swift:501-503`) notifies `CullNotes.note(cx, cz)`. On the very next frame, `SceneRenderer` re-runs `fillColumn(slot, c)` → `deepWaterAbove(c, sy)` reads `AIR` (`0`) from empty `c.blocks` and returns **`false`**, wiping `SecInfo.deep` from the cull table for every hollow ocean chunk!
  - Likewise, every shell installed from disk `MeshCache` (`World.installShell`, `Sources/ChunkShells.swift:137-166`) starts with `c.blocks = BlockStore([])`, so `deepWaterAbove` is always `false` for it.
  - Because `deepNear = 80` blocks and `keepDataDistance` drops to 6–8 chunks (96–128 blocks) under Auto active distance, **most or all of the deep-ocean band past 96 blocks loses Ledger 383's seabed cull** during steady-state frigate sailing and saved-world launches. (It passed `--perfscenes --only deepsea` only because `loadSync` hadn't run `reshell()` yet.)
- **Recommended fix:** Compute a 32-bit `deepWaterMask: UInt32` (one bit per section `sy` with 10+ blocks of water above its top) on `Chunk` whenever blocks are available (before `hollow()`, or inside `Mesher.buildSection` / `World.install` and saved in `MeshCache` alongside `occ`), and have `SceneRenderer.deepWaterAbove` read `(c.deepWaterMask & (1 << sy)) != 0` when `c.hollow == true` (or unconditionally from the cached mask, updated on `blocksVersion`).
- **Expected effect:** Keeps Ledger 383's ~18% ocean quad/section savings alive across hollow shells and cached launches during long frigate voyages — directly helping the GPU-bound frigate leg hold view 12 at 72 fps.
- **Risk:** Very low (4 bytes per `Chunk` + 4 bytes in `MeshCache`).

### 3. Save-pipeline durability & data-loss gaps: unflushed `fieldQueue`, `loadBlockEntities` decoder mismatch, unguarded sync `maps.json`/`xporbs.json`, incomplete backup snapshots, and lost brewing progress
- **Evidence:**
  1. **`SaveManager.fieldQueue` is never flushed (`Sources/TerrainField.swift:258,284-309` vs `Sources/Save.swift:322`):** Legacy smooth worlds write `f.X.Z.lz` terrain edits on a separate private queue `SaveManager.fieldQueue`, but `SaveIO.flush()` only drains `SaveIO.queue`. On quit (`exit(0)`), `APP_CMD_PAUSE`, `WorldStore.copy`, or world switch, in-flight `f.X.Z.lz` writes are never waited on and can be lost.
  2. **Encoder/decoder mismatch on `blockentities.json` (`Sources/Save.swift:144-161` vs `:172-177,459-468`):** `saveBlockEntities` encodes via `SaveIO.write` → `SaveIO.encoder()` (which writes non-finite `Float`/`Double` as `"nan"`/`"inf"`). `loadBlockEntities` decodes both the primary file (`:146`) and backup (`:151`) with plain `JSONDecoder()`, which throws on `"nan"`/`"inf"`. A single corrupted `xp`, `delay`, `cooldown`, or `last` float in any `BlockEntity` (`Sources/BlockEntities.swift:11,21,25,29`) quarantines the **entire `blockentities.json`** — wiping every chest, furnace, shulker, sign, and lectern in the dimension (or rolling back up to 5 min).
  3. **Synchronous `maps.json` and `xporbs.json` bypass `SaveIO.storeJSON` (`Sources/Game.swift:732,739`):** On quit/pause (`background == false`), both files use `try? JSONEncoder().encode(...)` + `try? d.write(..., options: .atomic)` — silently swallowing storage-full errors (violating S2), omitting `fsync` (`h.synchronize()`, violating S3 dead-battery safety), and bypassing `SaveIO.encoder()` (`XPOrb.vel` is not checked for `isFinite` at `:736`).
  4. **`SaveIO.snapshotFiles` misses 7 world state files (`Sources/Save.swift:398-399`):** Rolling `backups/auto-1..3` snapshots omit `drops.json`, `trains.json`, `circuit.json`, `falling.json`, `tree-ghosts.json`, `pieces.json`, and `objects.json` (plus sub-dimension `nether/`, `end/`, `deep/` JSON files).
  5. **Brewing stands abort active brews on reload (`Sources/BlockEntities.swift:17,69,86,110` + `Sources/Potions.swift:198-199`):** `brewTime` is saved/loaded, but `brewIngredient` is omitted from `CodingKeys` and reloads as `0`; on the first tick after reload, `ing.item != brewIngredient` resets `brewTime = 0`, wasting fuel already consumed.
- **Recommended fix:** (a) Route `saveFieldEdits` through `SaveIO.queue` (or add `SaveManager.flushFieldEdits()` inside `SaveIO.flush()`). (b) Switch `loadBlockEntities` (`:146,151`) to `SaveIO.decoder()`. (c) Replace `:732` and `:739` in `Game.swift` with `SaveIO.storeJSON(...)`. (d) Add the missing world JSON files to `SaveIO.snapshotFiles`. (e) Save `brewIngredient` by item key (`Items.saveKey` / `SaveMigration.itemID`) in `BlockEntity`.
- **Expected effect:** Closes silent save-loss and whole-world-chest-wipe failure modes on Quest 3 (critical for player trust and Horizon Store reviews on a survival sandbox).
- **Risk:** Very low (all changes are backward-compatible with existing saves).

### 4. `deepLayerTick` and `buriedTick` skip hollow shells (`where !c.hollow`) — leaving the outer view distance an empty void when crossing between Hell and Ash Vault in the Deep
- **Evidence:**
  - `Sources/World.swift:2181-2196` (`deepLayerTick`): when the player is in the Deep's Hell band (`y >= 192`), `deferringDeepLayer` (`:2168-2177`) defers every Ash Vault section (`y < 192`) beyond `d = 1` as empty meshes (`s.deferred = true`, `c.deferredBuried += 1`). Once those far chunks pass `keepDataDistance`, `reshell()` converts them into hollow shells (`c.hollow = true`) whose Ash Vault sections are empty + `deferred = true`.
  - When the player descends through the Sealrock into the Ash Vault (`hell` flips `true → false`), line `2186` loops `for (k, c) in chunks where !c.hollow { undeferBuried(c) ... }` — **completely skipping every hollow shell in the shell band (`keepDataDistance + 1 ... renderDistance`)**.
  - Because `undeferBuried(c)` is never called on those shells, `c.needsMesh` remains `false`, so `reshell()` (`Sources/ChunkShells.swift:49`: `if max(abs(dx), abs(dz)) <= keepDataDistance || c.needsMesh`) never requests a refill either! The outer ring of the Ash Vault (or Hell when ascending back up) stays a blank void until the player physically walks within `keepDataDistance` of each chunk.
  - The same `where !c.hollow` filter in `buriedTick` (`Sources/World.swift:2255`) skips hollow shells at distance `d = 7..8` when the player goes underground (`buriedNearUnder = 8`) while `activeDistance == 4` (`keepDataDistance == 6`), leaving caves at 7–8 chunks unmeshed.
- **Recommended fix:** Remove `where !c.hollow` from the `undeferBuried(c)` path in both `deepLayerTick` (`:2186`) and `buriedTick` (`:2255-2257`, keeping `!c.hollow` only for the `deferSection` branch that reads `buriedLow`), and trigger `requestRefill(k)` when undeferring a hollow chunk (`c.needsMesh` becomes `true`, so `reshell()`/`neighbourhood()` will refill and mesh it on workers).
- **Expected effect:** Eliminates giant missing outer-ring voids after crossing the Sealrock in the Deep and ensures full 8-chunk underground cave visibility at low `activeDistance`.
- **Risk:** Low (refills run asynchronously on `JobPool` workers; verify Deep transition frame times with `--triptest`).

### 5. `borderSprings` treats hollow neighbor shells as open air — flooding fluid queues at every ocean/lava shell edge and risking main-thread `refillNow` hitches
- **Evidence:**
  - `Sources/World.swift:2425-2466`: when a newly loaded/generated chunk `c` runs `borderSprings(c)`, line `2428` checks `guard let n = chunks[ChunkKey(x: c.cx + dx, z: c.cz + dz)] else { continue }` with **no `guard !n.hollow` check**.
  - When `n` is a hollow shell (`n.blocks = BlockStore([])`), `n.blocks.raw(ib)` is `AIR` and `n.blocks.ground(ib)` is `false`, so `openB` (`:2445`) evaluates to **`true` for every single `y` from `1...top`**.
  - Along any ocean, lake, river, or underground lava-sea border where a full chunk `c` meets a cached/hollow shell `n`, `borderSprings` enqueues **every border water/lava cell** (`fa != 0 && openB`) into `fluidPending` / `lavaPending`.
  - When `fluidTick` drains them outside `activeDistance`, `park(fluid:lava:)` (`Sources/FarTicks.swift:57-59`) appends them to an **un-deduplicated** `[ (IVec3, UInt8) ]` array in `parked[k]`, which later dumps back into `fluidPending` when the player approaches. Worse, if a `hotZone` (frigate shelling, `World.heat`) activates `c` while `n` is still hollow and `y` is above `n.height` (or `n` is refilled lazily), `setFluid` into `n` calls `editing(n)` → synchronous `refillNow(n)` (**12–30 ms main-thread hitch**).
- **Recommended fix:** Add `guard !n.hollow else { continue }` at `Sources/World.swift:2428`, and call `borderSprings(c)` at the end of `World.refill` (`Sources/ChunkShells.swift:130`) once a shell actually receives its blocks back. Also deduplicate `parked` (or use a `Set`) in `FarTicks.swift:57-66`.
- **Expected effect:** Eliminates bogus ocean/lava fluid-queue storms along shell boundaries during flight/sailing and prevents surprise main-thread `refillNow` spikes.
- **Risk:** Very low.

### 6. Cleared sections never reset stale `Chunk.light[sy]` — leaving ghost torch glow and shadows in empty air after demolishing structures
- **Evidence:**
  - `Sources/Mesher.swift:490,507`: when a section becomes completely empty (e.g. a player demolishes a torch-lit house, fells a tree canopy, or a frigate shells a tower down to air), `buildSection` hits the quick-exit path and returns `SectionMesh(opaque: [], trans: [], light: nil)`.
  - `Sources/World.swift:1693-1695` (`apply`): `if let l = m.light { c.light[sy] = l }` — when `m.light == nil`, **`c.light[sy]` is left untouched**, permanently keeping the old 4,096-byte light array from before the section was cleared.
  - `Sources/World.swift:551-559` (`lightAt`): while Ledger 90 (`:558`) clamps stale sky light to `15` above `c.height`, it **still returns `Int(l & 15)` (ghost block-light from destroyed torches/lamps)**, and if any overhang/roof remains higher in the column (`y <= c.height`), it returns both stale sky and stale block light. Mobs, particles, dropped items, and held items walking through the cleared area glow from phantom torches or sit in phantom dark patches until chunk reload.
- **Recommended fix:** Distinguish "deferred buried section" (`deferSection`, which intentionally keeps prior light) from "genuinely empty section" in `SectionMesh` (e.g., `var clearLight = false`, set on `Mesher.swift:490,507`, or return `Mesher.fullSky` when above `h9` and `nil` + `clearLight = true` otherwise), and set `c.light[sy] = nil` in `World.apply` when `m.clearLight` is true (allowing `lightAt` to fall back to live heightmap light and freeing the 4 KB array).
- **Expected effect:** Removes ghost lighting/shadows after mining, tree-felling, and base destruction, and frees 4 KB per emptied section.
- **Risk:** Very low (double-check `deferSection` at `World.swift:2144-2150` keeps `clearLight = false`).

### 7. Streaming & memory-lifecycle leaks: `World.unloadAll` retains `Chunk`s across dimension switches, `remeshSoon` double-schedules urgent `AdaptiveGround` jobs, and `MeshArena.trim` pins up to 64 MB of spare/active slabs
- **Evidence:**
  1. **Retained `Chunk`s on dimension switch (`Sources/World.swift:2756-2768`):** `World.unloadAll()` moves `chunks` off-frame to free memory when leaving a dimension, but **never clears `dirtyChunks`, `held`, or `parked`** (`World.swift:1040,1640`, `FarTicks.swift:59`). Every dirty or settling `Chunk` (and its blocks, field arrays, light, and `MeshSlice`s) stays strongly retained in RAM until the player returns to that dimension.
  2. **Double-scheduled urgent `AdaptiveGround` redraws on every player edit (`Sources/World.swift:1407,1446` + `Sources/Chunk.swift:120-123`):** On Quest (`fieldTerrain && AdaptiveGround.enabled`), `remeshSoon` submits a fast non-adaptive mesh to `quickQueue` (`c.meshJobsOut += 1`) and immediately executes `c.sections[sy].version += 1` (`:1407`) **without setting `World.backgroundEdits = true`**. `Section.version.didSet` marks `c.urgent = true`, so on the very next frame `World.update` (`:1949-1958`, where `c.meshJobsOut < 2` passes) immediately launches the slow `AdaptiveGround` redraw as a **`front: true`** worker job on `workQueue` *in parallel with* `quickQueue`, consuming a front worker slot and stealing throughput from terrain streaming on every placed/broken block.
  3. **`MeshArena.trim()` leaves `spare` and an empty active `slab` pinned (`Sources/MeshArena.swift:190,244-260`):** `trim()` only frees slabs where `s !== slab` and never clears `spare`. On Quest (`slabSize = 32 MB`), lowering view distance or switching worlds can leave up to **64 MB** (`slab` + `spare`) permanently allocated in `MeshArena.shared`.
- **Recommended fix:** (a) Clear `dirtyChunks.removeAll()`, `held.removeAll()`, and `parked.removeAll()` inside `World.unloadAll()` (also releasing them on the background queue alongside `gone`). (b) Wrap `c.sections[sy].version += 1` in `remeshSoon` (`:1407`) and `remeshSync` (`:1446`) with `World.backgroundEdits = true` (restoring prior value in `defer`) so the follow-up adaptive simplification meshes in background order instead of jumping the queue. (c) In `MeshArena.trim()`, also drop `spare = nil` (when `!spareAsked`), and if `slab?.live == 0` with no in-flight fence (`!s.starts.values.contains { $0.after > completed }`), release `slab` and reset `bump = 0`.
- **Expected effect:** Eliminates retained chunk memory across Overworld/Emberdeep/Deep/Hollow portal trips, frees up to 64 MB of unused GPU slab memory on view drops, and stops single block edits from launching duplicate urgent worker jobs.
- **Risk:** Very low.
