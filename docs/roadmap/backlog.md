# Sunderfall backlog (live)

Rules (Remington; full history in backlog-archive.md):
- WHO WORKS WHAT (Oct 24 evening): the "Sunderfall open lane" thread owns every open item. The old lane, builder 2 and the tough-builder agent are retired.
- OPEN BRIEFS (Remington, Oct 24 00:57; replaces the old "write 6-12 steps" rule): items give the goal, his words and everything known, not instructions. You are trusted to dig in and pick the approach the evidence points to, even if it differs from anything suggested. Numbered steps in older items are context and ideas, not orders; where an item and what you find disagree, follow what you find and say why in the note.
- BLOOM, DON'T PATCH (Remington, Oct 25 10:31; replaces the old "one and done" rule): his words: "I am growing a little upset with the fixes, I want to do the opposite of 1 and done. When I give a fix, it should be like a flower blooming. You find anything the fix is possibly related to and fix everything. Example: I want weight physics and connection physics so when I put titanium on a wood house for example, it collapses. How it should not be interpreted: I must make a wood house, put titanium on it? And make sure the house collapses and done. How it should be: I just assign weights to every block and connection durabilities and anything else the physics could entail. If I run into any issues doing this or trade offs I think Remington should know I'll tell him, I'll run many many tests to make sure everything works correctly and if I see any bugs on the way I'll fix them too."
- NO SILENT HANGS (Oct 23, after an 11-hour stall): no command, build or wait runs longer than 20 minutes; wrap builds and tests in `timeout 20m`. If it trips, kill it, write one line in the item, move on. Push and merge each finished item before starting the next; never hold finished items for one shared build. Headset or Mac-only checks are skipped in the cloud.
- POLYGONS ARE BACK (Remington, Oct 24 16:06): P431 (block world) is reversed by P432. Old polygon items count again; POLYGON STRICT applies as before.
- NO TEXT: no instructional or hint text in play (toasts, tutorials, tips, objective pop-ups); use in-world cues.
- When every open item is done or claimed, stop.
- IP: inspiration only. No coined names from Halo, GoldenEye, Red Dead, Minecraft or real military units in player-visible text (tools/namecheck.py --coined). The WW2 layer is fictional: no swastikas, SS runes, Iron Crosses or real insignia.
- Quest 3 is the product: 72 fps in the busiest scene.
- Item format: `P<n>. text`. Status tags only: [DONE ...], [CLAIMED: ...], [ON HOLD by Remington]; plus the owner tag [HIGH AGENT]. Never write those words inside an item's text (the stop hook counts them).
- PUSH BACK, DON'T WORK AROUND (Remington, Oct 18): if an item runs into a cost, limit or conflict (frame rate, memory, a rule above, missing access, something only the headset can show) and the only way through would be cutting scope, lowering a setting, capping or hiding the feature, faking it, or building a weaker version, do not do that. Stop that part and tag the item "[CLAIMED: BLOCKED, needs Remington: <what stopped you, the numbers, and the options you see>]", push the note, and move to the next item. A clear "I couldn't do X because Y" is always better than a quiet half-version.
- MEASURE PERFORMANCE WORK: any item that touches rendering, view distance, world loading or simulation must report frame time at the setting it is about (host build with the headset's compiler settings, busiest scene) in its PR, before and after. If the number misses the target, that is a BLOCKED note, not a DONE.
- CHECK EVERY PART BEFORE CLAIMING (Remington, Oct 19 audit): before tagging an item BUILT, DONE or BLOCKED, go through every lettered part (a), (b)... and every numbered step in its text one by one and write in the note: done (PR), or not done and why. Nothing may be left unmentioned; a part not done means the item is not built.
- BLOCKED IS THE LAST STEP, NOT THE FIRST: tag BLOCKED only after every step the item lists has been built and measured. If one step hits a wall, build the others first, then block with the numbers from all of them.
- Read backlog-archive.md only when an item points there; it holds finished items, old sections and design history (THE GAME'S SPINE, THE POLYGON DIRECTION).
